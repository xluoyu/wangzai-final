# 终稿路由

本文件负责判断用户请求的“成品形态 + 平台”是否已开放。

## 两个维度

### 成品形态

| 形态 | 状态 | 规则文件 |
|---|---|---|
| 口播稿 | 已开放 | `references/formats/oral.md` |
| 文章稿 | 已开放（当前仅公众号） | `references/formats/article.md` |

### 平台

| 平台 | 状态 | 规则文件 |
|---|---|---|
| 抖音 | 已开放 | `references/platforms/douyin.md` |
| 公众号 | 已开放（当前仅文章稿） | `references/platforms/wechat-official.md` |
| 知乎 | 预留，未开放 | `references/platforms/zhihu.md` |

## 当前支持矩阵

| 形态 | 平台 | 是否可生成 |
|---|---|---|
| 口播稿 | 抖音 | 可以 |
| 口播稿 | 公众号 | 不可以 |
| 口播稿 | 知乎 | 不可以 |
| 文章稿 | 抖音 | 不可以 |
| 文章稿 | 公众号 | 可以 |
| 文章稿 | 知乎 | 不可以 |

## 路由规则

1. 用户没说形态，但说“抖音稿 / 短视频稿 / 口播稿”：按 `口播稿 + 抖音`。
2. 用户没说平台，但说“口播稿”：默认按 `抖音 + 口播稿`，除非上下文指定其他平台。
3. 用户说“公众号文章 / 微信公众号稿 / 文章稿”，且没有指定其他平台：按 `文章稿 + 公众号`。
4. 用户只说“文章稿”：默认按 `文章稿 + 公众号`，除非上下文指定其他平台。
5. 用户明确要求知乎文章或公众号口播：按对应组合判断，不要擅自替换形态。
6. 未开放组合的回复方式：

```text
当前 wangzai-final 目前只开放“抖音 + 口播稿”和“微信公众号 + 文章稿”。
你这次要的是 <形态 + 平台>，对应规则还没建好。
可以先改成已开放的组合，或者先补这个平台/形态的规则。
```

## 扩展新组合时

新增支持时要同时补三处：

1. 对应 `formats/*.md` 或 `platforms/*.md` 的规则文件。
2. 本文件的支持矩阵。
3. `SKILL.md` 的“当前已开放组合”说明。
